> ไฟล์นี้คือ **แหล่งความจริงเดียวของความคืบหน้า V1.1** — ทุกครั้งที่ทำงานต่อ (หลัง token reset หรือ context ถูกสรุป)
> ให้เริ่มจากข้อ "วิธีทำงานต่อ" ด้านล่าง
>
> สัญลักษณ์: `[ ]` ยังไม่ทำ · `[x]` เสร็จและผ่านการตรวจแล้ว · `[~]` ทำบางส่วน (มีหมายเหตุ) · 🔑 ต้องการข้อมูล/บัญชีจากเจ้าของโปรเจกต์

## วิธีทำงานต่อ (Resume protocol)

1. `git pull` branch `claude/restaurant-saas-master-prompt-s0yy8e` แล้วเปิดไฟล์นี้
2. เลือก **ข้อแรกที่ยังไม่ติ๊ก** ในเฟสที่เลขน้อยที่สุด (ข้าม 🔑 ที่ยังไม่มีข้อมูล — ทำส่วนที่ไม่ต้องใช้ข้อมูลนั้นไปก่อน)
3. ทำงาน → ตรวจตาม "เกณฑ์ผ่าน" ของเฟส → ติ๊กในไฟล์นี้ + เขียนหมายเหตุสั้นๆ ใน "บันทึกความคืบหน้า"
4. commit + push (CI ต้องเขียว) แล้วทำข้อถัดไป
5. ทุกเฟสจบ → อัปเดต docs/scorecard และสรุปให้เจ้าของโปรเจกต์

**เกณฑ์ผ่านทุกข้อ:** `pnpm typecheck` · `pnpm test` (รวม SQL e2e + API กับ Postgres จริง) · `pnpm build` ผ่าน;
หน้าเว็บที่แก้ต้องทำงานได้ **ทั้งโหมด demo และโหมด API** และ axe = 0 violations

## เฟส 2 — API ให้ครบตามที่หน้าเว็บใช้ (พร้อมเทสต์)

- [ ] 2.1 `GET /v1/shop` — ข้อมูลตั้งต้นทั้งร้านในคำขอเดียว (tenant settings, branches+tables+stations, channels, payment methods, categories, menu+prices+modifiers+recipes, ingredients, roles+permissions, members, suppliers+items, plan)
- [ ] 2.2 รายการที่ยังขาด: purchase orders, receipts, stock movements ล่าสุด, stock counts, expenses, day closes, shifts, expected receipts
- [ ] 2.3 คำสั่งเมนู: แก้ราคา/สถานะ/สูตร (`PATCH /v1/menu-items/{id}`), toggle รายการในตั๋วครัว
- [ ] 2.4 คำสั่งทีม: แก้พนักงาน/ตำแหน่ง/สาขา/วงเงิน, ปิด-เปิดใช้งาน, ตั้ง PIN ใหม่, ตั้งสิทธิ์ตำแหน่ง
- [ ] 2.5 คำสั่งตั้งค่า: ร้าน, สาขา (แก้/เพิ่ม), ช่องทาง + GP แบบมีวันเริ่มมีผล, ช่องทางรับเงิน/PromptPay, ยืนยันรับเงินสดอย่างเดียว, เปลี่ยนแพ็กเกจ
- [ ] 2.6 ค่าใช้จ่ายตามหมวด (map หมวด → บัญชี) + ใบสั่งซื้อจากคำแนะนำ
- [ ] 2.7 รายงาน: `/v1/reports/summary` ให้โครงสร้างเท่ากับ selector ฝั่งเว็บ (totals, waterfall, channels, items engineered, days, hours, branches) + `/v1/reports/today` (ยอดวันนี้ vs สัปดาห์ก่อนเวลาเดียวกัน, spark 14 วัน)
- [ ] 2.8 OpenAPI + contract tests ครบทุก endpoint ใหม่

## เฟส 3 — Data layer ฝั่งเว็บ

- [ ] 3.1 `DataSource` interface: loaders (bootstrap/slices), commands (ทุกคำสั่งที่ UI ใช้), queries (reports, today)
- [ ] 3.2 Demo adapter ห่อ engine เดิม (พฤติกรรมเหมือนเดิม เทสต์เดิมผ่าน)
- [ ] 3.3 HTTP client: token, `X-Tenant-Id`, `Idempotency-Key`, timeout/retry, แปลง error → `ERROR_CATALOG`
- [ ] 3.4 DTO mappers API → client state (สตางค์, id, camelCase) + unit tests
- [ ] 3.5 เลือก adapter ด้วย `NEXT_PUBLIC_DATA_SOURCE` + หน้าเลือก "ทดลองร้านตัวอย่าง / เชื่อมต่อร้านจริง"
- [ ] 3.6 Approval token เดียวกันทั้งสองโหมด (demo = member id, api = approval id)
