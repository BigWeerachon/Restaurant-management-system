## 5. ข้อจำกัดที่ต้องรู้ (หมวด H = 88)

**ต้องใช้บัญชีหรือการตัดสินใจของเจ้าของโปรเจกต์ (ยังไม่ได้ทำ ไม่ได้แกล้งทำ):**

1. **Supabase Auth จริง** — โค้ดเว็บ/API พร้อมและทดสอบกับ GoTrue จำลอง แต่ยังไม่เคยต่อโปรเจกต์ Supabase จริง (ต้องมี URL/anon key; LINE Login ถ้าต้องการ) ตอนนี้ใช้ `AUTH_MODE=local` ที่เหมาะกับ dev/CI เท่านั้น
2. **ผู้ให้บริการรับบัตร/พร้อมเพย์** — ตอนนี้ออกใบแจ้งหนี้ให้ลูกค้าโอน/พร้อมเพย์ แล้วทีมงานยืนยันผ่าน webhook ที่ลงลายมือชื่อ ยังไม่มีการตัดบัตรอัตโนมัติ
3. **ที่ deploy API + Postgres** — เว็บโหมดเดโมอยู่บน Vercel แต่ API ยังไม่ได้ deploy จึงยังไม่มี: การสำรอง/กู้ข้อมูลที่ซ้อมแล้ว, collector รับ trace/metric และ alert ตาม SLO, การทดลองหลาย instance ([10-slo](10-slo.md) วัดบนเครื่องเดียว)

**สิ่งที่ยังไม่ได้พิสูจน์:**

4. **Mobile performance ต่ำกว่า V1** (85–94 เทียบ 93–100) — สาเหตุและสิ่งที่แก้แล้ว/ยังไม่แก้อยู่ในข้อ 2
5. **เครื่องพิมพ์ความร้อนจริง** — พิมพ์ตรงผ่าน USB/Serial/Bluetooth ทดสอบกับเครื่องพิมพ์จำลอง (ไบต์ที่ได้ถอดรหัสกลับเป็นข้อความตรงกับใบเสร็จ) แต่ยังไม่เคยลองกับเครื่องจริง และ WebUSB/Serial/Bluetooth ใช้ได้บน Chrome/Edge ผ่าน https เท่านั้น
6. **ใบกำกับภาษี** — รูปแบบยังไม่ได้ให้นักบัญชี/กรมสรรพากรตรวจ; ไม่มีใบลดหนี้ (บิลที่ออกใบเต็มรูปแล้วคืนเงินในระบบไม่ได้) และยังไม่มี e-Tax
7. **ออฟไลน์** ครอบคลุมสองคำสั่งที่พนักงานทำต่อหน้าลูกค้า (ส่งออเดอร์เข้าครัว, รับเงิน) ไม่ใช่ทุกหน้า; หลายเครื่องขายออฟไลน์พร้อมกันแล้วชนกันที่สต็อกยังไม่ได้ทดลองกับร้านจริง
8. **ประวัติขายในโหมด API เป็นข้อมูลสังเคราะห์และไม่ได้ปิดยอด** — `pnpm db:seed:history` ([checklist 1.2b](v1.1-checklist.md)) เติมบิล/การชำระ/กะ/สต็อก/ค่าใช้จ่าย 30 วันเป็นแถวโดยตรง (คำสั่งจริงผูกกับ `now()`) หน้าตาเหมือนที่คำสั่งสร้าง และมีเทสต์ตรวจว่ายอดรวม/ต้นทุน/สต็อก/ยอดกะตรงกัน แต่ไม่ใช่ยอดขายจริงของใคร; วันเหล่านั้นไม่ได้ปิดยอด (สมุดบัญชีไม่มีรายการรายได้ย้อนหลัง จนกว่าร้านจะปิดยอดเอง — ทำได้ ทดสอบแล้ว); ต้องเรียกเอง เพราะเทสต์เบราว์เซอร์ใน CI สมมติว่าร้านยังไม่เคยขาย
9. **การทดสอบอัตโนมัติรันบน Chromium เท่านั้น** — ไม่ได้ทดสอบ Safari/Firefox (`content-visibility`, `Intl`, service worker ต่างกัน); accessibility ทดสอบด้วย axe — **ไม่ได้ทดสอบด้วย screen reader จริง** (VoiceOver/TalkBack); **ไม่มี usability test กับพนักงานร้านจริง**
10. การเทียบคู่แข่งอ้างอิงเอกสารสาธารณะ ไม่ได้ทดลองใช้ทุกระบบด้วยตนเอง
