# วิสัยทัศน์ผลิตภัณฑ์ (Product Vision)

## ปัญหา

ร้านอาหารและคาเฟ่ SME ในไทยมี POS ที่ "ขายของได้" อยู่แล้ว แต่ตัวเลขที่ใช้ตัดสินใจกระจัดกระจาย:

- **ยอดขาย** อยู่ใน POS
- **ต้นทุนวัตถุดิบ** อยู่ใน Excel
- **ค่า GP** อยู่ในแอปของแต่ละแพลตฟอร์ม
- **เงินเข้า** อยู่ในแอปธนาคาร
- **บิลซัพพลายเออร์** อยู่ในกระดาษ

ผลคือเจ้าของร้านจำนวนมาก **ขายดีแต่ไม่รู้ว่าเหลือเงินจริงเท่าไร** ตัวอย่างที่พบบ่อย:

- ขายผ่านเดลิเวอรี 100 บาท หลังหัก GP 30% และต้นทุนวัตถุดิบ เหลือน้อยกว่าขายหน้าร้านเกือบครึ่ง
- ค่าเช่าและเงินเดือนที่จ่ายก้อนใหญ่ทำให้บางสัปดาห์ดูขาดทุน
- ของเสียและของหายไม่มีใครเห็นเป็นตัวเงิน

อีกด้านหนึ่ง พนักงานหน้าร้าน (มักเป็นพาร์ทไทม์) ไม่มีเวลาเรียนระบบซับซ้อน

## คำตอบของ Sabai

**ระบบเดียว ข้อมูลชุดเดียว ตั้งแต่หน้าร้านถึงบัญชี — ที่พนักงานใช้ได้โดยไม่ต้องเรียน**

```
ขาย (POS) ──► ครัว (KDS) ──► ตัดสต็อกตามสูตร ──► ต้นทุนต่อจานจริง
   │                                              │
   ├─► ช่องทาง + GP ณ วันที่ขาย ───────────────────┤
   ├─► เงินที่ต้องเข้าธนาคาร ──► กระทบยอดอัตโนมัติ    ▼
   └─► ปิดยอด ──► บัญชีคู่อัตโนมัติ ──────► "เหลือเงินจริง"
รับของ ──► บิลค้างจ่าย ──► ราคาขึ้น? แจ้งผลกระทบต่อเมนู
```

## กลุ่มลูกค้า (ICP)

| กลุ่ม | ขนาด | ความเจ็บปวดหลัก | แพ็กเกจ |
|---|---|---|---|
| คาเฟ่/ร้านเล็ก | 1 สาขา 2–8 คน | ขายง่าย, PromptPay, รู้ว่ากำไรไหม | ฟรี / สตาร์ทเตอร์ |
| ร้านอาหารขายเดลิเวอรีเยอะ | 1–3 สาขา | GP กินกำไร, สต็อกหาย, กระทบยอดแพลตฟอร์ม | โปร |
| เครือร้าน/แฟรนไชส์เล็ก | 3–10 สาขา + ครัวกลาง | เทียบสาขา, โอนของ, ควบคุมสิทธิ์ | บิสิเนส |
| เครือใหญ่ | 10+ สาขา | SSO, API, วิเคราะห์ขั้นสูง | เอนเตอร์ไพรส์ |

## ตัวชี้วัดความสำเร็จ

| มิติ | ตัวชี้วัด | เป้า V1 |
|---|---|---|
| Activation | ร้านใหม่ขายบิลแรกได้ภายใน | ≤ 10 นาที |
| Learnability | พนักงานใหม่ขายบิลแรกโดยไม่มีคนสอน | ≤ 3 นาที |
| Speed | เวลาจากแตะเมนูถึงเห็นในตะกร้า | < 100 ms (local-first) |
| Trust | บิลผิดยอดจากระบบ | 0 (ราคาคำนวณซ้ำที่เซิร์ฟเวอร์) |
| Insight | เจ้าของเปิดรายงาน "เหลือเงินจริง" | ≥ 3 ครั้ง/สัปดาห์ |
| Retention | ร้านที่ใช้ต่อหลัง trial | ≥ 60% |

## ตำแหน่งในตลาด

ดูรายละเอียดคู่แข่งใน [research/market-ux-research.md](research/market-ux-research.md) และการเทียบเชิงคะแนนใน [08-scorecard.md](08-scorecard.md)

- **เทียบ POS ไทย** (FoodStory/Wongnai POS, Ocha, Loyverse): ขายได้เท่ากัน แต่ Sabai มีสูตร + สต็อก + การเงิน + กระทบยอดในระบบเดียว
- **เทียบระบบต่างประเทศ** (Toast, Square, MarketMan, Apicbase, Restaurant365): มาตรฐานใกล้เคียง แต่เข้าใจบริบทไทย
  (PromptPay, GP ที่เปลี่ยนตามช่วง, VAT/Service charge, วันทำการข้ามเที่ยงคืน, ภาษาไทย) และใช้ง่ายกว่าสำหรับ SME

## สิ่งที่ "ไม่ทำ" ใน V1 (เพื่อโฟกัส)

- ระบบจองโต๊ะ, loyalty/CRM, ร้านค้าออนไลน์ของตัวเอง
- e-Tax Invoice (อยู่ใน V2 — ต้องใช้ใบรับรองดิจิทัล)
- เชื่อม API แพลตฟอร์มเดลิเวอรีโดยตรง (V2 — ปัจจุบันบันทึกผ่านช่องทางขาย + กระทบยอดจากเงินเข้า)
- บัญชีแยกประเภทเต็มรูปแบบสำหรับนักบัญชี (ส่งออกให้โปรแกรมบัญชีแทน)
